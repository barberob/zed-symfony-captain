# Removed routes are reported across the whole project

LSP diagnostics only reach documents open in the editor, so deleting a route silently left every usage in an unopened file dangling. On each successful index rebuild the server diffs the new index against the previous healthy one; for every route name that disappeared it scans the project (`src/` and `templates/`, using the same PHP and Twig finders as the editor features) and emits one `window/showMessage` warning per removed route, listing each reference as `file:line`. Only removals trigger a scan — a rare event — so the project is never fully rescanned on a routine rebuild. Reporting is gated on both the previous and the new index build having succeeded (mirroring the health gate in `0002`), and route reference scanning degrades soft rather than killing the language server process when a single file misbehaves.
